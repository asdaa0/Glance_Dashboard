# Glance Dashboard — Hermes project rules

Glance dashboard config repo (`glance.yml` + page yaml files). Edited locally on this
Windows machine; served on the `ultra` server (host `ultra` in ~/.ssh/config) from
`~/.config/glance/dashboard/`, deployed via git.

## Post-task deploy — MANDATORY after every task in this project

After completing any task that touched this repo, before reporting the task done, run:

    bash scripts/deploy.sh "<one-line summary of the change>"

The script does three things: commits all changes to branch `ultra`, pushes to GitHub
(`origin/ultra`), then SSHes into host `ultra` and runs `git pull --ff-only origin ultra`
inside `~/.config/glance/dashboard/`.

- Never end a task with uncommitted changes in this repo.
- If the script fails, report the error — the task is not done until the deploy succeeds
  (or the failure is explained to the user).
- If nothing changed, still run it once: it skips the commit and re-syncs the server.

## Working conventions

- The working branch is `ultra` — not `main`. The script checks out `ultra` before committing.
- `glance.exe` is a local binary and `.env` is local-only; never reference their contents.
- Yaml pages: home.yml, markets.yml, rss.yml, games.yml, sports.yml, hosting.yml, theme.yml.
- Favicon icons: use each site's own `https://<domain>/favicon.ico`, never the
  google s2 proxy (404s for many trackers) and never query-string variants
  (some trackers return access-denied, e.g. turkseed.com even though it lists
  one in its own HTML).
- Bookmark favicons: ALL are embedded as base64 `data:` URIs (Glance passes
  unknown icon strings straight through as the img src, so nothing external
  is fetched). To add/update one: fetch real image bytes — try the site's
  own `/favicon.ico` first, with the google s2
  (`https://www.google.com/s2/favicons?domain=<d>&size=64`) as fallback for
  domains without a direct favicon — verify the magic bytes, embed the data
  URI in the yaml `icon:` property, and append the entry to ALL-store file
  `base64-icons.txt` (format: `<name>  <mime>  <data-uri>`); never one file
  per icon, and never an `assets/` folder or GitHub raw links.
- Do NOT run `glance.exe` locally with env/config experiments — running
  Glance locally is not the goal; the config only targets the `ultra` server.
- `assets-path` is not configured in glance.yml and must not be reintroduced;
  icon storage lives in yaml data URIs and `base64-icons.txt`.
